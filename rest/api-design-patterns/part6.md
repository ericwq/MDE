# 第 6 部分 安全与保障

人们很容易忘记，用户在使用 API 时偶尔会犯错误。
由于这些错误不幸是不可避免的，因此设计一个能让用户在错误发生时帮助最大限度地减少损失的 API 非常重要。
在接下来的几章中，我们将探讨旨在实现这一目标的设计模式。

在 [第 24 章](ch24.md) 中，我们将探讨版本控制和兼容性的高层概念，以及可用于 API 版本控制的策略。
在 [第 25 章](ch25.md) 中，我们将探讨类似 API 回收站的想法，以防止意外删除。
在 [第 26 章](ch26.md) 至 [第 28 章](ch28.md) 中，我们将探讨各种策略，
用于防止重复工作、在执行工作之前测试请求，以及保留资源更改历史，以便用户在需要时撤销更改。

在 [第 29 章](ch29.md) 中，我们将探讨在网络故障或其他问题发生时何时以及如何安全地重试请求。
最后，在 [第 30 章](ch30.md) 中，我们将探讨 API 服务如何安全地认证请求。
