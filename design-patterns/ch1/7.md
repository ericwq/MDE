# 1.7 如何选择设计模式

目录中有 20 多个设计模式可供选择，可能很难找到能处理某个特定设计问题的那个，尤其是当目录对你来说很新、不熟悉时。
以下是找到适合你问题的设计模式的几种不同方法：

- *考虑设计模式如何解决设计问题。*
[1.6 节](6.md) 讨论了设计模式如何帮助你找到合适的对象、确定对象粒度、指定对象接口，以及设计模式解决设计问题的其他几种方式。
参考这些讨论可以帮助指导你寻找正确的模式。

- *浏览意图部分。*
1.4 节（第 [8](4.md) 页）列出了目录中所有模式的意图部分。
通读每个模式的意图，找到一个或多个听起来与你的问题相关的模式。
你可以使用表 1.1（第 [10](5.md) 页）中呈现的分类方案来缩小搜索范围。

- *研究模式如何相互关联。*
图 1.1（第 [12](6.md#fig-1-6-1) 页）以图形方式显示了设计模式之间的关系。
研究这些关系可以帮助引导你找到正确的模式或模式组。

- *研究同类目的模式。*
目录（第 [79](../partII.md) 页）有三章，一章是创建型模式，另一章是结构型模式，第三章是行为型模式。
每章开头都有对这些模式的介绍性评论，并以一节比较和对照它们的部分结束。
这些部分让你深入了解同类目的模式之间的相似之处和差异。

- *检查一个重新设计的原因。*
看看从第 [24](6.md#redesign-reasons) 页开始的重新设计原因，看看你的问题是否涉及其中一个或多个。
然后看看帮助你避免这些重新设计原因的模式。

- *考虑你的设计中什么应当是可变的。*
这种方法与聚焦重新设计原因相反。
与其考虑什么可能迫使设计改变，不如考虑你希望能够在不重新设计的情况下改变什么。
这里的重点是封装变化的概念，这是许多设计模式的一个主题。
表 1.2 列出了设计模式让你能够独立改变的设计方面，从而让你无需重新设计就能改变它们。

*表 1.2：设计模式让你能够改变的设计方面*
| 分类 | 设计模式 | 可变化的方面 |
| ---- | ---- | ---- |
| **创建型（Creational）** | Abstract Factory (87) | 产品对象家族 |
| | Builder (97) | 组合对象的创建方式 |
| | Factory Method (107) | 要实例化的对象子类 |
| | Prototype (117) | 要实例化的对象所属类 |
| | Singleton (127) | 类的唯一实例 |
| **结构型（Structural）** | Adapter (139) | 对象的接口 |
| | Bridge (151) | 对象的实现 |
| | Composite (163) | 对象的结构与组合关系 |
| | Decorator (175) | 无需子类化即可为对象增加职责 |
| | Facade (185) | 子系统的接口 |
| | Flyweight (195) | 对象的存储开销 |
| | Proxy (207) | 对象的访问方式；对象所处位置 |
| **行为型（Behavioral）** | Chain of Responsibility (223) | 能够处理请求的对象 |
| | Command (233) | 请求的处理时机与处理方式 |
| | Interpreter (243) | 语言的文法与解释逻辑 |
| | Iterator (257) | 聚合对象元素的访问、遍历方式 |
| | Mediator (273) | 对象之间交互的方式以及参与交互的对象 |
| | Memento (283) | 需要在对象外部保存哪些私有信息，以及保存时机 |
| | Observer (293) | 依赖某个对象的对象数量；依赖对象如何保持状态同步 |
| | State (305) | 对象的状态 |
| | Strategy (315) | 算法 |
| | Template Method (325) | 算法的步骤 |
| | Visitor (331) | 可作用于对象、且无需修改对象所属类的操作 |
