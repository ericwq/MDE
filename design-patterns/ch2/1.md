# 2.1 设计问题

我们将考察 Lexi 设计中的七个问题：

1. *文档结构。*
文档内部表示的选择几乎影响 Lexi 设计的每一个方面。
所有编辑、格式化、显示和文本分析都需要遍历该表示。
我们组织这些信息的方式将影响应用其余部分的设计。

2. *格式化。*
Lexi 究竟如何把文本和图形排成行与列？
哪些对象负责实施不同的格式化策略？
这些策略如何与文档的内部表示交互？

3. *装饰用户界面。*
Lexi 的用户界面包含滚动条、边框和投影，它们装饰了所见即所得的文档界面。
这些装饰很可能随 Lexi 用户界面的演进而变化。
因此，重要的是能够方便地添加和移除装饰，而不影响应用的其余部分。

4. *支持多种外观与风格标准。*
Lexi 应当能够轻松适应 Motif、Presentation Manager (PM) 等不同的外观与风格标准，而无需重大修改。

5. *支持多个窗口系统。*
不同的外观与风格标准通常实现在不同的窗口系统之上。
Lexi 的设计应当尽可能独立于窗口系统。

6. *用户操作。*
用户通过各种用户界面来控制 Lexi，包括按钮和下拉菜单。
这些界面背后的功能分散在应用中的各个对象里。
这里的挑战在于，为访问这些分散的功能以及撤销其效果提供一种统一的机制。

7. *拼写检查与断词。*
Lexi 如何支持诸如检查拼写错误的单词、确定断词位置这类分析性操作？
我们如何尽量减少为新增分析性操作而必须修改的类数量？

我们在接下来的各节中讨论这些设计问题。
每个问题都伴随一组目标，以及关于如何达成这些目标的约束。
我们先详细解释目标与约束，再提出具体解决方案。
问题及其解决方案将说明一种或多种设计模式。
每个问题的讨论最终都会简要介绍相关的模式。
