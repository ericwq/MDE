# 第 4 章 结构型模式

结构型模式关注类和对象如何被组合以形成更大的结构。
结构型类模式使用继承来组合接口或实现。
作为一个简单的例子，考虑多重继承如何把两个或更多类混合成一个。
结果是一个结合了其父类属性的类。
这种模式对于让独立开发的类库协同工作特别有用。
另一个例子是 [Adapter (139)](1.md) 模式的类形式。
一般来说，适配器让一个接口（被适配者的接口）符合另一个接口，从而提供不同接口的统一抽象。
类适配器通过私有继承一个被适配者类来实现这一点。
然后适配器用被适配者的接口来表达自己的接口。

结构型对象模式不是组合接口或实现，而是描述组合对象以实现新功能的方式。
对象组合增加的灵活性来自在运行时改变组合的能力，而这是静态类组合不可能做到的。

[Composite (163)](3.md) 是结构型对象模式的一个例子。
它描述如何构建一个由两类对象的类组成的类层次结构：原始对象和复合对象。
复合对象让你可以把原始对象和其他复合对象组合成任意复杂的结构。
在 [Proxy (207)](7.md) 模式中，代理充当另一个对象的便利替身或占位符。
代理可以以许多方式使用。
它可以充当远程地址空间中对象的本地代表。
它可以表示一个应当按需加载的大对象。
它可以保护对敏感对象的访问。
代理为对象的特定属性提供了一层间接。
因此它们可以限制、增强或改变这些属性。

[Flyweight (195)](6.md) 模式定义了一种共享对象的结构。
对象被共享至少有两个原因：效率和一致性。
Flyweight 关注为了空间效率而共享。
使用大量对象的应用程序必须仔细注意每个对象的成本。
通过共享对象而不是复制它们，可以节省大量空间。
但只有当对象不定义依赖语境的状态时，它们才能被共享。
Flyweight 对象没有这种状态。
它们执行任务所需的任何额外信息会在需要时传递给它们。
由于没有依赖语境的状态，Flyweight 对象可以被自由共享。

Flyweight 展示如何制造大量小对象，而 [Facade (185)](5.md) 展示如何让单个对象代表整个子系统。
外观是一组对象的代表。
外观通过把消息转发给它所代表的对象来履行其职责。
[Bridge (151)](2.md) 模式把一个对象的抽象与其实现分离，以便你可以独立改变它们。

[Decorator (175)](4.md) 描述如何动态地给对象添加职责。
Decorator 是一种结构型模式，它递归地组合对象，以允许开放数量的额外职责。
例如，一个包含用户界面组件的 Decorator 对象可以给该组件添加像边框或阴影这样的装饰，也可以添加像滚动和缩放这样的功能。
我们可以简单地通过把一个 Decorator 对象嵌套在另一个中来添加两个装饰，更多装饰依此类推。
为实现这一点，每个 Decorator 对象必须符合其组件的接口，并且必须把消息转发给它。
Decorator 可以在转发消息之前或之后完成自己的工作（例如围绕组件绘制边框）。

许多结构型模式在某种程度上相互关联。
我们将在本章末尾讨论这些关系。
