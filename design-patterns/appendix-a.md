# 附录 A 术语表

### abstract class（抽象类）

以定义接口为主要目的的类。
抽象类把部分或全部实现推迟到子类。
抽象类不能被实例化。

### abstract coupling（抽象耦合）

若类 A 持有对抽象类 B 的引用，则称类 A 与 B 抽象耦合。
之所以称之为抽象耦合，是因为 A 引用的是某类对象，而不是某个具体对象。

### abstract operation（抽象操作）

只声明签名而不实现的操作。
在 C++ 中，抽象操作对应于纯虚成员函数。

### acquaintance relationship（相识关系）

若一个类引用另一个类，则称它与那个类相识。

### aggregate object（聚合对象）

由子对象组成的对象。
这些子对象称为该聚合的部件，聚合对它们负责。

### aggregation relationship（聚合关系）

聚合对象与其部件之间的关系。
类为其实例（即聚合对象）定义这种关系。

### black-box reuse（黑盒复用）

一种基于对象组合的复用方式。
被组合的对象彼此不暴露内部细节，因而类似于 “黑盒”。

### class（类）

类定义一个对象的接口与实现。
它规定对象的内部表示，并定义该对象可以执行的操作。

### class diagram（类图）

描绘各个类、它们的内部结构与操作，以及它们之间静态关系的图。

### class operation（类操作）

作用于类而非某个个体对象的操作。
在 C++ 中，类操作称为静态成员函数。

### concrete class（具体类）

不含抽象操作的类。它可以被实例化。

### constructor（构造函数）

在 C++ 中，自动调用以初始化新实例的操作。

### coupling（耦合）

软件各组件相互依赖的程度。

### delegation（委托）

一种实现机制：一个对象把请求转发或委托给另一个对象。
受托者代表原对象执行该请求。

### design pattern（设计模式）

设计模式系统地命名、阐明其动机并解释一种通用设计，用以应对面向对象系统中反复出现的设计问题。
它描述问题、解决方案、何时应用该解决方案，以及它的效果。
它还给出实现提示与示例。
解决方案是解决问题的一组对象和类的通用排布。
解决方案会针对特定语境加以定制和实现，以解决该问题。

### destructor（析构函数）

在 C++ 中，自动调用以完成一个即将被删除的对象之收尾工作的操作。

### dynamic binding（动态绑定）

在运行时把请求关联到某个对象及其某个操作。
在 C++ 中，只有虚函数是动态绑定的。

### encapsulation（封装）

把表示与实现隐藏在对象内部所得到的结果。
表示不可见，也无法从对象外部直接访问。
操作是访问和修改对象表示的唯一途径。

### framework（框架）

一组相互协作的类，它们构成针对某类特定软件的可复用设计。
框架通过把设计分解为抽象类并定义它们的职责与协作，提供架构层面的指导。
开发者通过为框架类派生子类并组合其实例，使框架适应特定应用。

### friend class（友元类）

在 C++ 中，对某个类的操作与数据拥有与该类自身相同访问权限的类。
（正文中该词保留英文 friend。）

### inheritance（继承）

用另一个实体来定义一个实体的关系。
类继承用一个或多个父类定义一个新类。
新类从父类继承其接口与实现。
新类称为子类（在 C++ 中也称派生类）。
类继承结合了接口继承与实现继承。
接口继承用一个或多个已有接口定义新接口。
实现继承用一个或多个已有实现定义新实现。

### instance variable（实例变量）

构成对象表示的一部分的数据。
C++ 使用 “数据成员” 这一术语。

### interaction diagram（交互图）

展示对象之间请求流动的图。

### interface（接口）

一个对象的各操作所定义的全部签名之集合。
接口描述了对象能够响应的请求集合。

### metaclass（元类）

在 Smalltalk 中，类本身也是对象。元类就是类对象的类。

### mixin class（混入类）

为通过继承与其他类组合而设计的类。混入类通常是抽象的。

### object（对象）

在运行时把数据与作用于这些数据的过程打包在一起的实体。

### object composition（对象组合）

通过组装或组合对象来获得更复杂的行为。

### object diagram（对象图）

描绘运行时某个特定对象结构的图。

### object reference（对象引用）

标识另一个对象的值。

### operation（操作）

对象的数据只能通过它的操作来操纵。
对象在收到请求时执行一个操作。
在 C++ 中，操作称为成员函数。Smalltalk 使用 “方法” 这一术语。

### overriding（重写）

在子类中重新定义（从父类继承来的）一个操作。

### parameterized type（参数化类型）

让某些构成类型保持未指定的类型。
未指定的类型在使用处以参数形式提供。
在 C++ 中，参数化类型称为模板。

### parent class（父类）

另一个类由之继承的类。
同义词有超类（Smalltalk）、基类（C++）和祖先类。

### polymorphism（多态）

在运行时用接口相匹配的对象相互替换的能力。

### private inheritance（私有继承）

在 C++ 中，指仅为获得其实现而被继承的类。

### protocol（协议）

把接口的概念扩展到包含请求的允许序列。

### receiver（接收者）

请求的目标对象。

### request（请求）

对象在收到另一个对象的相应请求时执行一个操作。
请求的常见同义词是消息。

### signature（签名）

操作的签名定义其名称、参数和返回值。

### subclass（子类）

从另一个类继承的类。在 C++ 中，子类称为派生类。

### subsystem（子系统）

一组独立的类，它们协作完成一组职责。

### subtype（子类型）

若一个类型的接口包含另一个类型的接口，则它是后者的子类型。

### supertype（超类型）

一个类型由之继承的父类型。

### toolkit（工具包）

提供有用功能、但不规定应用设计的一组类。

### type（类型）

某个特定接口的名字。

### white-box reuse（白盒复用）

一种基于类继承的复用方式。
子类复用父类的接口与实现，但它可能访问父类原本私有的部分。
