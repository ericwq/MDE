# 安全重构

## 所需技能

根据重构范围加载以下技能：
1. `framework:knowledge-priming`（始终使用）
2. `framework:context-anchoring`（始终使用）
3. `framework:learning-harvest`（始终使用）
4. `framework:collaborative-judgment`（始终使用）
5. `framework:clean-code`（始终使用）
6. `framework:test-quality`（始终使用）
7. `framework:design-first`（条件使用：重大结构变更）
8. `framework:architecture`（条件使用：层级位置和依赖方向）
9. `framework:domain-driven-design`（条件使用：聚合边界和领域行为）
10. `framework:secure-coding`（条件使用：安全敏感代码）

## 工作流程

### 步骤 1：建立重构上下文

从**当前痛点**开始，而非偏好抽象。确定目标区域、澄清为什么需要重构、用户期望改进什么。一句话总结意图：

> "重构 X 以改进 Y，同时保留 Z。"

**停止：** 如果无法清晰陈述改进目标和保留目标，在规划变更之前继续澄清。

### 步骤 2：定义保留边界

重构改变结构，**不改变行为**。在提出结构编辑之前明确保留契约。

列出必须保持不变的行为：公共 API 契约、领域不变量、持久化语义、事件发射、授权和安全态势等。同时列出明确的**范围外变更**。

### 步骤 3：提出高层结构计划

**零重构规则**：在用户批准目标结构和过渡计划之前，不进行结构代码变更。

呈现：当前结构问题、目标结构、迁移计划、保留边界、范围外项目。以明确的关卡结束：*"这个重构计划看起来正确吗？我应该继续步骤 4：特征测试吗？"*

### 步骤 4：首先添加特征保护

在改变结构之前，用测试锁定当前行为。识别已有的保护保留行为的测试，加强弱测试，为重要的隐式行为添加特征测试。偏好忠实捕获保留行为而不遗漏重要集成效果的最低级别测试。

### 步骤 5：选择重构策略和节奏

首选策略：提取并重定向、引入接缝然后迁移、将行为向内移动、拆分并合并。

节奏选项：逐片审查（推荐）、逐层审查、完全自主。

### 步骤 6：小步绿改重构

仅实施已批准保留边界和目标结构内的变更。对每片进行：一次结构改进 → 重新运行特征测试 → 应用原子自检 → 修复违规 → 收集判断决策。

**偏离规则**：如果实施揭示批准的重构计划不完整、不安全或需要改变保留行为，立即暂停并讨论。

### 步骤 7：验证保留和结构改进

重构仅在**两项**均满足时成功：1. 行为保留 2. 结构可衡量地改进。

### 步骤 8：捕获决策和剩余债务

使用 `framework:context-anchoring` 丰富行为，持久化重构范围、保留边界、目标结构、选择策略、关键文件变更和推迟的债务。收获经验，推荐 `/review`。
