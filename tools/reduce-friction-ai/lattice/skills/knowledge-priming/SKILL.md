# 知识预载

## 配置解析

1. 在仓库根目录查找 `.lattice/config.yaml`。
2. 如果找到，检查 `paths.knowledge_base` 是否存在自定义文档路径。
3. 如果该路径存在文档，读取完整文档。
4. **停止：在任何设计、实现或审查工作开始之前，将已加载的文档作为环境上下文应用。**
5. 如果没有配置、路径或文档 → 见"当文档不存在时"。

## 当文档不存在时

通知用户：

> 未找到项目知识库。AI 技能将从关于技术栈、架构和约定的通用假设出发运行。
>
> 要创建一个，触发 **knowledge-priming-refiner**——引导式访谈（约 10 个问题），生成一份简洁文档（约 50 行）。
>
> 也可以手动创建 `.lattice/standards/knowledge-base.md`，并在 `.lattice/config.yaml` 的 `paths.knowledge_base` 下引用。

不阻塞。在无知识库的情况下继续。

## 文档内容

| # | 章节 | 捕获内容 |
|---|---------|-----------------|
| 1 | **架构概述** | 应用类型、主要组件、它们如何交互 |
| 2 | **技术栈与版本** | 特定技术及版本号，包括"非 X"的澄清 |
| 3 | **精选知识来源** | 官方文档、受信任博客、内部参考（最多 5–10 个） |
| 4 | **项目结构** | 显示内容所在位置的目录布局 |
| 5 | **项目约定** | 其他技能无法从代码推断的项目特定约定 |

## 范围边界

| 关注点 | 所属 |
|---------|----------|
| 编码风格、命名原则、函数设计 | clean-code 原子 |
| 架构层级、依赖方向 | architecture 原子 |
| 领域建模、聚合设计 | domain-driven-design 原子 |
| 输入验证、注入防护 | secure-coding 原子 |
| 测试结构、断言质量 | test-quality 原子 |

知识预载回答*"我们在做什么？"*——而不是*"我们应该怎么写？"*
