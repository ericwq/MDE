# 领域驱动设计：默认原则

DDD 战术模式的嵌入默认值。可通过 SKILL.md 配置解析覆盖。

## 1. 聚合设计规则

### 一致性边界

聚合 = 每次事务后**必须**立即一致的对象集合。不是"相关联的事物"。具体来说：其组合状态必须满足原子性检查的不变量的对象。

### 大小启发法

从**最小可能聚合**开始：根实体 + 值对象。仅在事务性不变量强制时才添加内部实体。

### 通过标识引用

聚合仅通过 ID 引用其他聚合——绝不通过直接对象引用。

### 单事务规则

单个业务操作每个事务最多修改一个聚合。需要原子更新两个聚合？边界错误（合并）或通过领域事件接受最终一致性。

### 不变量归属

每个业务规则恰好属于一个聚合。规则跨越两个聚合？1) 边界错误——应为一个聚合。2) 一个聚合通过接收另一个的状态作为值来拥有规则。3) 规则是最终一致性问题——通过领域事件 + 补偿操作强制执行。

## 2. 实体模式

实体具有持久标识。基于标识判等。行为丰富的实体将业务规则封装为方法。

## 3. 值对象模式

值对象没有标识，完全由其属性定义。不可变——操作返回新实例。自验证——构造函数成功则值有效。基于属性判等。

常见值对象目录：Money、Email、PhoneNumber、Address、DateRange、Quantity、Percentage、Typed ID、Status。

## 4. 领域服务规则

封装跨多个实体或值对象的业务逻辑。无状态。纯领域计算——无 I/O。

## 5. 领域事件模式

过去时态命名（OrderPlaced，非 PlaceOrder）。携带足够数据描述发生了什么。用于跨聚合协调和通知关切。

## 6. 仓库模式

每个聚合根一个仓库。集合语义。接口在领域层，实现在基础设施。返回完整构建的聚合。

## 7. 对象创建模式

复杂聚合创建应封装验证和组装。多种有效方法——取决于组装复杂性和团队约定。
