# 知识预载精炼器

## 目的

此精炼器引导结构化对话，创建项目特定的知识库文档。文档捕获项目的身份——其技术栈、架构、目录布局以及塑造团队工作方式的受信任来源。可以将其视为回答一个问题："AI 需要了解*这个项目*的什么，以避免默认使用通用互联网模式？"

## 这将产出什么

- **输出**：`.lattice/standards/knowledge-base.md`（或来自 `.lattice/config.yaml` → `paths.knowledge_base` 的自定义路径）
- **模式**：覆盖是标准方法——每个项目的知识库都是独特的，因此没有通用默认值可供叠加
- **配置键**：`.lattice/config.yaml` 中的 `paths.knowledge_base`
- **模板**：读取 `./assets/template.md` 获取完整文档结构和访谈指导注释
- **消费者**：`knowledge-priming` 原子通过配置解析加载此文档，并将其作为环境项目上下文提供给所有技能和分子

## 范围边界

知识预载捕获**项目身份和技术上下文**。它有意排除了其他技能覆盖的关注点。如果编写的内容是在教导*如何编写代码*，它属于上述原子之一，不在此处。知识预载回答"我们在做什么？"——而不是"我们应该怎么写？"

## 引导方法

- **一次一个章节。** 按顺序浏览 5 个章节。
- **先展示示例。** 对每个章节，解释它捕获什么，展示具体示例，然后询问用户。
- **记录用户内容，而非讨论。** 输出文档读起来像参考资料。
- **鼓励具体性。** "Fastify 4.x"有用；"现代框架"没有用。版本号很重要，因为 API 在版本之间会变化。
- **保持精简。** 目标在 3 页/约 50 行聚焦内容以内。每个 token 都在竞争上下文窗口空间。

## 5 个章节

| # | 章节 | 捕获内容 |
|---|---------|-----------------|
| 1 | **架构概述** | 大局：什么类型的应用、主要组件、它们如何交互 |
| 2 | **技术栈与版本** | 特定技术及版本号，包括"非 X"的澄清 |
| 3 | **精选知识来源** | 团队依赖的官方文档、受信任博客、内部参考（最多 5–10 个） |
| 4 | **项目结构** | 显示内容所在位置的目录布局 |
| 5 | **项目约定** | 其他技能无法推断的简要项目特定约定（可选，精简） |

## 文档质量检查

在编写最终文档之前，验证：

- [ ] 内容具体，不通用（"Fastify 4.x"而非"现代框架"）
- [ ] 技术栈条目在适用时包含版本号
- [ ] "非 X"澄清引导 AI 远离不适用的常见默认值
- [ ] 精选来源限制在 5–10 个高价值条目
- [ ] 无编码指南（命名规则、代码示例、反模式）——这些属于其他技能
- [ ] 文档保持在约 50 行聚焦内容以内（不包括标题和格式）
- [ ] 新开发者会觉得这对理解*这个项目是什么*有用吗？
- [ ] **不是重定向存根**——5 个章节中少于 3 个已填充，或正文主要指向另一个文件 → 在写入前停止
