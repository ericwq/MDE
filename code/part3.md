# 第三部分 架构

软件系统的架构是由构建它的人赋予该系统的形状。
该形状的形式体现为：将系统划分为组件、这些组件的排列方式，以及这些组件之间相互通信的方式。

该形状的目的是促进其中所包含的软件系统的开发、部署、运行和维护。

> 这种促进背后的策略是：尽可能长时间地保留尽可能多的选项。

也许这句话让你感到惊讶。
也许你认为软件架构的目标是让系统正常工作。
当然，我们希望系统正常工作，并且系统的架构必须将其作为最高优先级之一来支持。

然而，系统的架构与系统是否能够正常工作关系甚微。
外面有很多架构糟糕的系统，它们运行得也很好。
它们的问题不在于运行，而在于其部署、维护和持续开发。

这并不是说架构在支持系统正确行为方面不起作用。
它当然起作用，而且这个作用是关键的。
但这个作用是被动且表面性的，而不是主动或本质性的。
系统的架构几乎无法在行为层面留下什么选项（即使有也很少）。

架构的主要目的是支持系统的生命周期。
良好的架构使系统易于理解、易于开发、易于维护、易于部署。
其最终目标是最小化系统的生命周期成本，并最大化程序员的生产力。
