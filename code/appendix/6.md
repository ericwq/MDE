## John 对 PrimeGenerator 的重写

**JOHN：**<br/>
我提到过，我请我软件设计课上的学生重写 PrimeGenerator 来修复其所有设计问题。
以下是我的重写（注意：这是在我们就讨论开始前写的；鉴于我在讨论中学到的东西，我现在会更改几个注释，但我保留了它的原始形式）：

```java
package literatePrimes;
import java.util.ArrayList;

public class PrimeGenerator2 {
    /**
     * Computes the first prime numbers; the return value contains the
     * computed primes, in increasing order of size.
     * @param n
     * How many prime numbers to compute.
     */
    public static int[] generate(int n) {
        int[] primes = new int[n];

        // Used to test efficiently (without division) whether a candidate
        // is a multiple of a previously-encountered prime number.
        // Each entry here contains an odd multiple of the corresponding
        // entry in primes. Entries increase monotonically.
        int[] multiples = new int[n];

        // Index of the last value in multiples that we need to consider
        // when testing candidates (all elements after this are greater
        // than our current candidate, so they don't need to be
        // considered).
        int lastMultiple = 0;

        // Number of valid entries in primes.
        int primesFound = 1;
        primes[0] = 2;
        multiples[0] = 4;

        // Each iteration through this loop considers one candidate; skip
        // the even numbers, since they can't be prime.
        candidates:
        for (int candidate = 3; primesFound < n; candidate += 2) {
            if (candidate >= multiples[lastMultiple]) {
                lastMultiple++;
            }

            // Each iteration of this loop tests the candidate against one
            // potential prime factor. Skip the first factor (2) since we
            // only consider odd candidates.
            for (int i = 1; i <= lastMultiple; i++) {
                while (multiples[i] < candidate) {
                    multiples[i] += 2*primes[i];
                }
                if (multiples[i] == candidate) {
                    continue candidates;
                }
            }

            primes[primesFound] = candidate;

            // Start with the prime's square here, rather than 3x the
            // prime. This saves time and is safe because all of the
            // intervening multiples will be detected by smaller prime
            // numbers. As an example, consider the prime 7: the value
            // in multiples will start at 49; 21 will be ruled out as a
            // multiple of 3, and 35 will be ruled out as a multiple of 5,
            // so 49 is the first multiple that won't be ruled out by a
            // smaller prime.
            multiples[primesFound] = candidate*candidate;
            primesFound++;
        }

        return primes;
    }
}
```

每个人都可以阅读这个并自己决定是否认为它比原始版本更容易理解。
我想提到几个整体的事情。

- 只有一个方法。我没有细分它，因为我觉得该方法已经自然地划分为不同的和可理解的部分。
在我看来，提取方法不会显著提高可读性。
当学生重写代码时，他们通常有两三个方法，那些通常也可以。

- 有很多注释。
我极少写这种注释密度的代码。
我写的大多数方法在主体中没有注释，只有一个描述接口的头注释。
但这段代码是微妙和棘手的，所以它需要很多注释来使微妙之处对读者清晰。
一些注释的长度很长是一个危险信号，表明我很难找到对代码的清晰简单的解释。
即使有所有额外的解释材料，这个版本也比原始版本稍短（65 行对 70 行）。

**UB：**<br/>
我假设这是一个完全的重写。
我猜你是努力从《Clean Code》中理解算法，然后从头开始写了这个。
如果是这样，那很公平。

在《Clean Code》中，我重构了 Knuth 的算法，以给它一些结构。
这与完全重写不同。

话虽如此，你的版本比 Knuth 的或我的都要好得多。

我在 18 年前写了那一章，所以自从我看到并理解这个算法以来已经很久了。
当我第一次看到你的挑战时，我想：“哦，我能理解我自己的代码！”
但不行。
我能看到所有的活动部件，但我无法理解为什么那些活动部件会生成质数列表。

然后，我看了你的代码。
我遇到了同样的问题。
我能看到所有的活动部件，都有注释，但我仍然无法理解为什么那些活动部件会生成质数列表。

理解这个需要大量的盯着天花板、闭上眼睛、可视化、骑我的自行车。

我遇到的问题之一是你写的注释。
让我们逐一来看。

```java
/**
 * Computes the first prime numbers; the return value contains the
 * computed primes, in increasing order of size.
 * @param n
 * How many prime numbers to compute.
 */
public static int[] generate(int n) {
```

在我看来，这更好写成：

```java
public static int[] generateNPrimeNumbers(int n) {
```

或者，如果必须：

```java
// Return the first n prime numbers
public static int[] generate(int n) {
```

我不反对 Javadoc 作为一种规则；但我只在绝对必要时才写它们。
我也厌恶那些从方法签名中完全明显的描述和 @param 语句。

下一个注释花了我好 20 分钟来琢磨。

```java
// Used to test efficiently (without division) whether a candidate
// is a multiple of a previously-encountered prime number. Each entry
// here contains an odd multiple of the corresponding entry in
// primes. Entries increase monotonically.
```

首先，我不确定为什么 “除法” 这个说法是必要的。
我是老派，所以我期望每个人都知道在内部循环中避免除法，如果它可以避免的话。
但也许我错了……

此外，埃拉托斯特尼筛法不做除法，并且比这个算法更容易理解和解释。
那么为什么是这个特定的算法？
我认为 Knuth 试图节省内存 —— 在 1982 年，节省内存很重要。
这个算法比筛法使用少得多的内存。

然后是这句话：`Each entry here contains an odd multiple...`。
我看了看它，然后看了看代码，我看到了 `multiples[0] = 4;`。

“那不是奇数，”
我对自己说。
“所以也许他的意思是偶数。”

于是，我向下看，看到了 `multiples[i] += 2*primes[i];`。

“那是加一个偶数！”
我对自己说。
“我很确定他的意思是说 ‘偶数’ 而不是 ‘奇数’。”

我还没有弄清楚 `multiples` 数组是什么。
所以我认为它里面有偶数完全是合理的，而你的注释只是一个可以理解的字词转换。
毕竟，注释没有编译器，所以它们会受到人类经常用文字犯的那种错误的影响。

只有当我看到 `multiples[primesFound] = candidate*candidate;` 时，我才开始质疑事情。如果候选数是质数，那么质数乘以质数在 2 之后的所有情况下不都应该是奇数吗？
我不得不在脑海中做数学来证明：(2n + 1)(2n + 1) = 4n^2 + 4n + 1 … 是的，那是奇数。

好的，所以 `multiples` 数组里全是奇数倍数，除了第一个元素，因为它是 2 的倍数。

所以也许那个注释应该是：

```java
// multiples of corresponding prime.
```

或者也许我们应该把数组的名字改成类似 `primeMultiples` 并完全去掉注释。

继续下一个注释：

```java
// Each iteration of this loop tests the candidate against one
// potential prime factor. Skip the first factor (2) since we
// only consider odd candidates.
```

这不太有道理。
它所说的代码是：

```java
for (int i = 1; i <= lastMultiple; i++) {
    while (multiples[i] < candidate) {
```

正如我们现在所了解的，`multiples` 数组是质数倍数的数组。
这个循环不是在测试候选数对质数因子，而是在测试它对当前的质数倍数。

对我来说幸运的是，第三或第四次读到这个注释时，我意识到你真正的意思是要用 `multiples` 这个词。
但我能知道这一点的唯一方法是理解算法。
而当我理解算法时，为什么我还需要注释？

这给我留下了一个最后的问题：到底为什么要有：

```java
multiples[primesFound] = candidate*candidate;
```

为什么是平方？这说不通。所以我把它改成了：

```java
multiples[primesFound] = candidate;
```

它工作得很好。所以这一定是某种优化。

你对此的解释性注释是：

```java
// Start with the prime's square here, rather than 3x the prime.
// This saves time and is safe because all of the intervening
// multiples will be detected by smaller prime numbers. As an
// example, consider the prime 7: the value in multiples will
// start at 49; 21 will be ruled out as a multiple of 3, and
// 35 will be ruled out as a multiple of 5, so 49 is the first
// multiple that won't be ruled out by a smaller prime.
```

最初几次读的时候，我完全不明白它在说什么。
它只是一堆数字的乱码。

我盯着天花板，闭上眼睛去想象。
我看不到它。
所以我进行了一次长时间的、沉思的自行车骑行，在那期间我意识到，2 的质数倍数会在某个时刻包含 2*3，然后是 2*5。
所以 `multiples` 数组会在某个时刻包含比它们所代表的质数更大的质数的倍数。
然后我顿悟了！

突然间一切都有意义了。
我意识到 `multiples` 数组等同于我们在埃拉托斯特尼筛法中使用的布尔数组 —— 但有一个非常有趣的转折。
如果你在白板上做筛法，你可以擦除所有小于候选数的数字，只划掉那些是所有先前质数的下一个倍数的数字。

这个解释现在对我来说完全合理，但我敢打赌那些正在阅读它的人正在为它困惑。
这个想法就是很难解释。

最后，我回到你的注释，可以明白你在说什么了。
