## 两个程序员的故事

**UB：**<br/>
底线是你我都落入了同样的陷阱。
我在 18 年前重构了那个旧算法，我以为所有那些方法和变量名称会使我的意图清晰 —— 因为我理解那个算法。

你在不久前写了那段代码，并用你认为会解释你意图的注释装饰了它 —— 因为你理解那个算法。

但我的名字在 18 年后没有帮助我。
它们也没有帮助你或你的学生。
你的注释也没有帮助我。

我们在盒子里面，试图与站在外面、看不到我们所看到的的人沟通。

底线是，向一个对你试图解释的细节不熟悉的人解释某件事是非常困难的。
通常，只有在读者自己琢磨出细节之后，我们的解释才有意义。

**JOHN：**<br/>
你上面的讨论中有很多东西，但我认为这一切都归结为一件事：你不喜欢我写的注释。
正如我之前提到的，复杂性在读者的眼中：如果你说我的注释令人困惑或没有帮助你理解代码，那么我必须认真对待这一点。

同时，你已经明确表示你一般不太看重注释的价值。
你的偏好是基本上不给这段代码（或任何代码）写注释。
你在上面争辩说，注释根本没有什么可以做的来使代码更容易理解；理解代码的唯一方法是阅读代码。
那是一种逃避。

**UB：**<br/>
抱歉打断你，但我认为你夸大了我的立场。
我当然没有说过注释从来不会有帮助。
有时，当然，它们是有帮助的。
我说过的是我只有在代码验证它们时才信任它们。
有时注释会使那种验证变得容易得多。

**JOHN：**<br/>
你一直说你有时发现注释有用，但现实是 “有时” 在你的代码中几乎从不发生。
当我们看你对我代码的修订时，我们会看到这一点。

现在回到我的观点。
为了编写我们代码的各种版本，你和我必须积累大量关于算法的知识，比如为什么一个质数的第一个倍数是它的平方是可以的。
不幸的是，并非所有这些知识都能在代码中表示。
我们有专业责任尽最大努力在注释中传达这些知识，以便读者不必一遍又一遍地重新构建它。
即使产生的注释不完美，它们也会使代码更容易理解。

如果像这样的情况发生在现实生活中，我会和你和其他人一起改进我的注释。
例如，我会问你问题，以更好地了解为什么 “平方质数” 的注释似乎没有帮助到你。

- 注释中是否有误导或令人困惑的地方？
- 你在自行车骑行中是否获得了某个重要信息，突然使事情变得清晰？

我也会把注释给其他几个人看，听听他们的看法。
然后，我会重写注释来改进它。

鉴于你对注释的根本不信任，我认为很可能即使在重写之后，你仍然会认为注释没有价值。
在这种情况下，我会把注释给其他人看，特别是那些对注释有更积极看法的人，并听取他们的意见。
只要注释没有误导性，并且至少有一些人觉得它有帮助，我就会保留它。

现在让我讨论你反对的两个具体注释。
第一个注释是 `multiples` 变量的注释：

```java
// Used to test efficiently (without division) whether a candidate
// is a multiple of a previously-encountered prime number. Each entry
// here contains an odd multiple of the corresponding entry in
// primes. Entries increase monotonically.
```

这个注释中有一个你指出的错误（第一个条目不是奇数）；好发现！
然后你争辩说注释中的大部分信息是不必要的，并提出了这个替代方案：

```java
// multiples of corresponding prime.
```

你在这里省略了太多有用的信息。
例如，我认为假设读者会自己弄清楚动机是避免除法是不安全的。
明确陈述这些假设和动机总是更好，这样就不会有混淆。
我认为让读者知道这些条目从不减少是有帮助的。
我会简单地修复错误，保留所有信息：

```java
// Used to test efficiently (without division) whether a candidate
// is a multiple of a previously-encountered prime number. Each entry
// (except the first, which is never used) contains an odd multiple of
// the corresponding entry in primes. Entries increase monotonically.
```

第二个注释是这个，关于 `for` 循环的：

```java
// Each iteration of this loop tests the candidate against one
// potential prime factor. Skip the first factor (2) since we
// only consider odd candidates.
```

你反对这个注释，因为循环的代码实际上并没有测试候选数对质数因子；它测试它对一个倍数。
当我写这样的实现注释时，我的目标不是重述代码；像那样的注释通常不会提供太多价值。
这里的目标是说出代码在逻辑意义上在做什么，而不是它如何做。
从这个意义上说，注释是正确的。

然而，如果注释引起读者的困惑，那么它就不是一个好的注释。
因此，我会重写这个注释，以明确它描述了代码的抽象功能，而不是它的精确行为：

```java
// Each iteration of this loop considers one existing prime, ruling
// out the candidate if it is a multiple of that prime. Skip the
// first prime (2) since we only consider odd candidates.
```

总之，我同意你的说法 “向一个对你试图解释的细节不熟悉的人解释某件事是非常困难的”。
然而，作为程序员，这正是我们的责任。

**UB：**<br/>
我很高兴我们达成了一致。
我们也同意让其他人审查代码并就代码和注释提出建议。
