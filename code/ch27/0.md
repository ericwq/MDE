# 第 27 章 整洁架构

<center><img src="../imgs/fig-ch27-0.png" width="40%"></center><br/>

在过去的几十年里，我们看到了一系列关于系统架构的想法。
这些包括：

- 六边形架构（又名端口与适配器），由 Alistair Cockburn 开发，并被 Steve Freeman 和 Nat Pryce 在其精彩的著作《测试驱动的面向对象软件开发》中所采用。

- 数据、上下文和交互（DCI）架构，来自 James Coplien 和 Trygve Reenskaug。

- 边界-控制-实体（BCE）架构，由 Ivar Jacobson 在其著作《Object-Oriented Software Engineering: A Use-Case Driven Approach》中引入 (Addison-Wesley, 1992)。

尽管这些架构在细节上各有不同，但它们非常相似。
它们都有相同的目标，即关注点分离。
它们都通过将软件划分为层来实现这种分离。
每个架构都至少有一层用于业务规则，另一层用于用户和系统接口。

这些架构中的每一种都能产生具有以下特征的系统：

- 独立于框架。
该架构不依赖于某个功能丰富的软件库的存在。
这允许你将此类框架用作工具 (tools)，而不是迫使你将系统塞入它们有限的约束中。

- 可测试。
业务规则可以在没有 UI、数据库、Web 服务器或任何其他外部元素的情况下进行测试。

- 独立于 UI。
UI 可以轻松更改，而无需更改系统的其余部分。
例如，Web UI 可以被控制台 UI 替换，而无需更改业务规则。

- 独立于数据库。
你可以将 Oracle 或 SQL Server 替换为 Mongo、Bigtable、CouchDB 或其他数据库。
你的业务规则不绑定到数据库。

- 独立于任何外部机构。
实际上，你的业务规则对外部世界的接口一无所知。
