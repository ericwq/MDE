## 类与模块 vs 文件

在一些面向对象语言中，如 Java，一个文件只能声明一个公共可用的类。
其他语言，如 C++、TypeScript 和 Ruby，允许你在一个文件中声明多个类，甚至将一个类拆分到多个文件中。

更令人困惑的是，一些语言（包括 OO 和函数式）允许你声明命名空间。
这可以帮助你在更大的系统中避免名称冲突。
它们还可以帮助你组织相关的概念。

大多数函数式语言 ——例如 Clojure、Elixir 和 Haskell—— 允许你将函数组织到一个文件中的多个独立模块中。
即使对于在语言中不直接支持模块/命名空间的语言（JavaScript 就是一个例子），你也可以在单个源文件中组织多个 “虚拟” 模块。

仅仅因为你可以这样做并不意味着你应该这样做。
<ins>通常，坚持每个源文件一个模块或类。
你将为自己和你的开发团队减少麻烦</ins>。

当然，在软件开发中一切都是权衡，因此例外总是存在的。
你可能会发现在同一个源文件中声明其他非常紧密相关的类是有用的，例如小的结构体（如 Java 中的 record）或异常类型。
也许它们只被同一个文件中的其他类型使用，或者它们总是出现在同样涉及文件主要类型的客户端代码中。

（当然，所有这些对那些胆敢完全不将代码组织成文件的狡猾的 Smalltalk 程序员来说意义不大。）

<ins>但是，是的，在大多数情况下，类 <=> 文件，或模块 <=> 文件，或诸如此类。
在本章的讨论中，我们将文件部分视为大多无关紧要。
我们将专注于如何正确地将概念分组到类和模块中，而不管它们是如何部署到文件中的</ins>。
