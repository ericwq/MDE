## 准则 3：小捆绑

这种准则是在我写第二版的过程中由 John Ousterhout 向我提出的。
它既不强制测试和代码的顺序，也不强制 TDD 和 TCR 那种极小的周期。
周期时间更长，可能差一个数量级。
是分钟而不是秒。

这个想法很简单。
程序员编写一个小捆绑 (small bundles) 的代码和测试来实现某个结果。
他们可以先编写代码。他们可以先编写测试。
他们可以穿插编写代码和测试。
但他们将以那个小捆绑具有高测试覆盖率且所有测试通过来结束。

如果你习惯于 TDD 或 TCR，你可能会觉得捆绑准则是一个稀释的妥协。
我不同意。
它可能是一个较软的仪式；但它可以同样有效。
任何准则都可能被滥用，任何准则都可能被尊重。
如果程序员通过保持小捆绑并测试每一个分支和条件来尊重这种准则，那么他们将产生一个他们可以以生命相托的测试套件。
因此，它与编写整洁代码完全兼容。
