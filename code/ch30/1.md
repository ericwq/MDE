## Dijkstra

Edsger Wybe Dijkstra 于 1930 年出生在鹿特丹。
他在鹿特丹轰炸和德国对荷兰的占领中幸存下来，并于 1948 年以数学、物理、化学和生物学的最高成绩高中毕业。

1952 年 3 月，21 岁时，就在我出生前九个月，他在阿姆斯特丹数学中心找到了一份工作，成为荷兰第一位程序员。

1957 年，他与 Maria Debets 结婚。
当时在荷兰，你必须在婚礼仪式中说明自己的职业。
当局不愿接受 “程序员” 作为他的职业。
他们从未听说过这样的职业。
所以他选择了 “理论物理学家”。

1955 年，在担任程序员三年后，当时他还是一名学生，他得出结论，编程的智力挑战大于理论物理学的智力挑战，因此他选择编程作为他的长期职业。

在做出这个决定时，他与他的上司 Adriaan van Wijngaarden 商议。
Dijkstra 担心没有人定义过编程的学科或科学，因此他将不会被认真对待。
他的上司回答说，Dijkstra 很可能正是能够使编程成为一门科学的人之一。

为了追求这个目标，Dijkstra 被软件是一个形式系统、一种数学的想法所吸引。
他推理说，软件可以成为一个类似欧几里得《几何原本》的数学结构 —— 一个由公设、证明、定理和引理组成的系统。
于是他开始创建软件证明的语言和准则。

### 证明正确性

Dijkstra 意识到我们只能使用三种技术来证明算法的正确性：枚举、归纳和抽象。
枚举用于证明序列中的两个语句，或被布尔表达式选择的两个语句是正确的。
归纳用于证明循环是正确的。
抽象用于将语句组分解为更小的可证明块。

如果这听起来很难，它确实是。
为了说明这有多难，我在下面包含了一个用于计算整数余数的简单 Java 程序，以及我在其下的手写证明。¹

¹ 这是从 Dijkstra 著作中的翻译成 Java 的一个演示。

```java
public static int remainder(int numerator, int denominator) {
    assert(numerator >= 0 && denominator > 0);
    int r = numerator;
    int dd = denominator;
    while (dd<=r)
        dd *= 2;
    while (dd != denominator) {
        dd /= 2;
        if (dd <= r)
            r -= dd;
    }
    return r;
}
```

别担心。
我不期望你阅读我的证明。
我只是想让你感受一下这样的证明需要什么。

事实上，这是 Dijkstra 曾痛苦抱怨的事情：

> “我当然不敢建议（至少在目前！）每当程序员在他的程序中编写一个简单的循环时，他都有责任提供这样的证明。
如果是这样，他将永远无法编写任何规模的程序。”²

² [SP72](../bib.md#sp72) 。

Dijkstra 的希望是，通过创建一个定理库，类似于欧几里得的《几何原本》，这样的证明会变得更加实用。

但 Dijkstra 没有理解软件会变得多么普遍和无处不在。
在那些早期，他没有预见到计算机的数量将超过人口，大量的软件将运行在我们家的墙壁里、口袋里和手腕上。
如果他知道了，他会意识到他设想的定理库对于任何凡人来说都太庞大了。

因此，Dijkstra 对程序进行显式数学证明的梦想已经逐渐消失，几乎被遗忘。
哦，还有一些坚持者希望形式化证明能够复兴，但他们的愿景并没有深入到整个软件行业。

但虽然梦想可能已经过去，它在身后留下了一些深刻的东西。
我们今天使用的东西，几乎没有思考过。
