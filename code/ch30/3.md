## 功能分解

1968 年，Dijkstra 的想法并没有立即流行。
我们中的大多数人使用依赖 GOTO 的语言。
因此，放弃 GOTO 或对 GOTO 施加纪律的想法是令人厌恶的。

关于 Dijkstra 思想的争论持续了几年。
在那些日子里，我们没有互联网，所以我们没有使用 Facebook 表情包或火焰战。
但我们确实给当时主要软件期刊的编辑写信。

那些信充满了愤怒。
有些人声称 Dijkstra 是神。
其他人声称他是傻瓜。
就像今天的社交媒体；只是更慢。

但随着时间的推移，争论放缓了，Dijkstra 的立场获得了越来越多的支持。
直到今天，我们使用的大多数语言根本就没有 GOTO。

如今，我们都是结构化程序员，因为我们的语言不给我们选择。

我们都用顺序、选择和迭代构建我们的程序。
我们中很少有人经常使用不受约束的 GOTO 语句。

由这三种结构组成程序的一个意想不到的副作用是一种称为 *功能分解 (functional decomposition)* 的技术。

功能分解是一个过程，你从程序的顶层开始，递归地将其分解成越来越小的可证明单元。
事实上，这是结构化编程背后的推理过程。
结构化程序员通过这种递归分解从上到下推理成越来越小的可证明函数。

结构化编程和功能分解之间的这种联系是 70 年代和 80 年代结构化革命的基础。

像 Ed Yourdon、Larry Constantine、Tom DeMarco 和 Meilir Page-Jones 这样的人在那几十年里推广了结构化分析和结构化设计的技术。
