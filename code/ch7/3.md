## Switch 语句

很难做出一个小的 `switch` 语句。⁴ 
也很难让一个 `switch` 语句只做一件事。
就其本质而言，`switch` 语句总是做 N 件事。
不幸的是，我们不能总是避免 `switch` 语句，但我们可以确保每个 `switch` 语句都埋藏在一个低层模块中，并且从不重复。
当然，我们通过多态来实现这一点。

⁴ 当然，我也把 `if/else` 链包括在内。

例如，考虑从上面的例子中提取出来的这个 `switch` 语句。

```go
func (rental Rental) determineAmount() float64 {
    amount := 0.0
    switch rental.movie.movieType {
    case NewRelease:
        amount += float64(rental.daysRented * 3)
    case Regular:
        amount += 2
        if rental.daysRented > 2 {
            amount += float64(rental.daysRented-2) * 1.5
        }
    case Childrens:
        amount += 1.5
        if rental.daysRented > 3 {
            amount += float64(rental.daysRented-3) * 1.5
        }
    }
    return amount
}
```

这个函数有几个问题。

1. 它比我想要的大，而且当添加新的电影类型时它会增长。
2. 它显然做了不止一件事。
3. 它违反了 *单一职责原则 (SRP)* ⁵，因为存在多个需要改变的理由。

⁵ 参见 [第 19 章](../ch19/0.md) “SOLID原则”。

4. 它违反了 *开闭原则 (OCP)* ⁶，因为每当添加新类型时它都必须改变。

⁶ 同上。

但可能这个函数最糟糕的问题是有无数其他函数将具有相同的结构。
例如，我们已经有了 `determinePoints`，而且我们可能以后会有 `applyCoupon` 或 `getAgeRestriction`。
不难想到许多其他的。
所有这些都将包含一个相关的 `switch` 语句。

解决这个问题的一个好方法是将 `switch` 语句埋藏在 *抽象工厂 (Abstract Factory)* ⁷ 的地下室里，绝不让任何人看到它。
该工厂使用 `switch` 语句来创建 `RentalType` 派生类的适当实例。

⁷ [GOF95](../bib.md#gof95) 。

```go
type RentalTypeFactory interface {
    make(typeName string) RentalType
}

type RentalTypeFactoryImpl struct{}

func (r RentalTypeFactoryImpl) make(typeName string) RentalType {
    switch typeName {
    case "childrens":
        return ChildrensRental{}
    case "new release":
        return NewReleaseRental{}
    case "regular":
        return RegularRental{}
    }
    return nil
}
```

我对 `switch` 语句的一般规则是：如果它们只出现一次，被定位在像 `main` 这样的具体模块中，用于创建多态对象，
并且被隐藏在接口后面以便系统的其余部分看不到它们，那么它们是可以被容忍的。
