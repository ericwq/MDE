## 命令查询分离

CQS (Command Query Separation) 是许多程序员在适当的时候采用的一种约定。
我使用过它，它通常非常有帮助。
在实践中应该考虑它。

<ins>根据 CQS 约定，函数要么做某事，要么回答某事，但不能两者兼有。
要么一个函数是一个产生副作用的命令（即，它改变系统的状态），要么它是一个返回某些信息的查询</ins>。

两者都做可能会导致混淆。
例如，考虑以下函数：

```java
public boolean set(String attribute, String value);
```

这个函数设置一个命名属性的值，如果成功则返回 `true`，如果不存在这样的属性则返回 `false`。
这导致了像下面这样奇怪的语句：

```java
if (set("username", "unclebob"))...
```

从读者的角度来看。
这意味着什么？
它是在问 `"username"` 属性之前是否被设置为 `"unclebob"` ？
还是在问 `"username"` 属性是否被成功设置为 `"unclebob"` ？
从调用中很难推断出含义，因为不清楚 `set` 这个词是动词还是形容词。

作者意图将 `set` 作为一个动词，但在 `if` 语句的上下文中，它感觉像一个形容词。
我们可以尝试通过将 `set` 函数重命名为 `setAndCheckIfExists` 来解决这个问题，但这对于 `if` 语句的可读性没有太大帮助。
真正的解决方案是将命令与查询分离，以便不会产生歧义。

```java
if (attributeExists("username")) {
    setAttribute("username", "unclebob");
    ...
}
```

<ins>但是，正如我所说，在某些情况下，遵守 CQS 是不切实际的，或者只是不方便</ins>。
例如，考虑以下代码：

```cpp
int top = stack.pop();
```

那行简单的代码违反了 CQS。
它查询了栈顶，同时也改变了栈的状态。

在像这样方便的情况下违反 CQS 有代价吗？
有：并发 (concurrency)。
如果 `pop` 函数没有通过适当使用信号量或锁来使其原子化，那么可能会出现竞争条件，导致栈顶在该对象被正确地从栈中移除之前被返回给两个不同的线程。

你们中的 C++ 程序员会认识到，C++ 标准模板库不允许你在单个语句中查询和修改容器。
在该库中，上面的 `pop` 操作需要两个符合 CQS 的语句：

```cpp
Thing top = myStack.top();
myStack.pop();
```

在 C++ 中，除了并发的原因之外，这样做的原因是 `Thing` 类可能会重写赋值运算符，³ 因此它可能会抛出异常。
如果 `pop` 操作既改变了栈又返回了栈顶，那么当赋值运算符抛出异常时，可能会使栈处于未知状态。

³ 没错，各位，在 C++ 中你可以重写对象的赋值运算符 `=`。

<ins>因此，尽管我不能声称在每种情况下都使用 CQS，但我认真对待这个建议，并且只在考虑了可能的结果之后才违反它</ins>。
