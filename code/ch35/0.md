# 第 35 章 诚实且公平地估算

> 8. 我将提供在幅度和精度上都诚实的估算。
没有合理的确定性，我不会做出承诺。

在本章中，我们将讨论估算项目和需要许多天或数周才能完成的大型任务。
这与我在《Clean Agile》¹ 一书中描述的估算小型任务和故事的敏捷实践不同。

¹ [Clean Agile](../bib.md#clean-agile) 。

知道如何估算是每个软件开发人员的一项基本技能；也是我们大多数人非常、非常不擅长的一项技能。

这项技能是必不可少的，因为每个企业在投入资源之前都需要大致知道某件事的成本。

不幸的是，我们未能理解估算实际上是什么，以及如何创建估算，导致了程序员与企业之间几乎灾难性的信任丧失。

现实中散落着数十亿美元的软件失败。
通常，这些失败是由于糟糕的估算造成的。
估算偏差 2 倍、3 倍甚至 4 或 5 倍并不罕见。
但为什么？
为什么估算如此难以准确？

主要是因为我们不理解估算实际上是什么，以及如何创建它们。

你看，为了使估算有用，它们必须是诚实的。
它们必须诚实地准确，它们必须诚实地精确。
但大多数估算两者都不是。
事实上，大多数估算都是谎言。
