# 第 29 章 行为或结构无缺陷

> 2. 我生产的代码将永远是我最好的工作成果。
我不会故意允许在行为或结构上有缺陷的代码积累。

记住，Kent Beck 曾经说过：“首先，让它工作。然后，让它正确。”

让程序工作只是第一步，也是最容易的一步。
第二步也是更难的一步是清理代码。

不幸的是，太多程序员认为一旦他们让程序工作，他们就完成了。
一旦它工作了，他们就继续下一个程序，然后下一个，再下一个。

在他们身后，他们留下了一段纠结、不可读的代码历史，拖慢了整个开发团队。

他们这样做是因为他们认为他们的价值在于速度。
他们知道他们薪水很高；所以他们觉得他们必须在短时间内交付大量的功能。

但软件是困难的，需要很多时间，所以他们觉得自己走得太慢了。
他们觉得自己在失败。
这种失败感产生了一种压力，使他们试图更快。
这让他们匆忙行事。

于是他们匆忙地让程序工作；然后他们宣布自己完成了 —— 因为，在他们心目中，已经花了太长时间。

项目经理不断敲击的脚没有帮助，但那不是真正的驱动因素。

我教很多课程。
在其中的许多课上，我给程序员小项目来编码。
我的目标是给他们一种编码体验，让他们可以尝试新的技术和新的纪律。
我不在乎他们是否真的完成了项目。
实际上，所有代码都将被丢弃。

我仍然看到人们在匆忙。
有些人下课了还呆在那里，只是为了做些完全没意义的事情。

所以，虽然老板的压力没有帮助，但真正的压力来自我们内部。
我们认为开发速度是我们自我价值的问题。
