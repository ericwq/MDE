# 第 21 章 持续设计

作者：Jeff Langr

产品负责人（以及其他帮助定义软件产品的人）确定了系统必须为其用户完成的一组最终目标。
开发人员则反过来以代码和配置的形式在系统中为这些目标中的每一个建立支持。
正如 Jack W. Reeves 在三十多年前教导我们的那样，这些代码（和配置 ¹ ）是 “设计” 的最终和确定的表示。²

¹ 例如，[PPP02](../bib.md#ppp02) ，http://www.butunclebob.com/ArticleS.UncleBob.PrinciplesOfOod ，以及 https://en.wikipedia.org/wiki/SOLID_(object-oriented_design) （或直接搜索 SOLID）。<br/>
² https://www.developerdotstar.com/mag/articles/reeves_design.html 。在 [PPP02](../bib.md#ppp02) 中重印。

“设计” 一词传统上有两个主要含义：
- 构建某物的计划
- 该事物当前状态所散发出的形式和功能

持续设计，也缩写为……等等，那个缩写已经被占用了。
我们可以在本章中只说完整的短语 “持续设计”。
最终，我们就直接称它为 “设计”，因为这是我们构建软件系统的最佳方式：一个接一个地做出有意识的设计决策。

正如我们所说：持续设计意味着我们持续规划如何容纳新的行为，并且每次我们添加新的行为时，我们的系统就有了一个新的设计。
大部分规划都发生在我们开始编写将提供新行为的代码时。

添加新代码或更新现有代码总是会改变设计，通常只是以非常小的方式改变。

设计不是项目开始时发生的模糊开发阶段。
它不仅仅是绘制关于系统需要看起来像什么的高层草图的活动。

设计是一种持续的活动。
我们系统的设计应该引起我们持续的关注，因为根据定义，它在持续变化。
这听起来很艰巨，但实际上，它比生成一组初始设计模型，然后假装之后可以忽略设计要容易得多。
