## 一切都要小、命名良好、组织有序、排列有序

如果你现在就停下来，只读那个标题，你就已经掌握了清理代码所需的大部分精髓。

<ins>保持一切小巧。
为那些小的元素选择能够向其他程序员传达信息的名称。
定义并维护一种结构和组织，以一种其他人可以轻松消费的方式呈现软件。
保持该组织内的元素排列有序，以便一个概念以合理和明智的方式紧随另一个概念</ins>。

请记住，你对代码的理解可能会偏向于你提供好的名称和结构的尝试；所以要努力让自己站在那些不理解代码的人的角度思考。

### 函数

<ins>函数应该很小。
大多数应该只有几行</ins>。
这允许它们有好的、描述性的名称，并促进关注点分离。
它确保每个函数做一件事，并且只做一件事。

让我们从名称开始。
如果你看到一段代码片段做了一些可以被合理命名的事情，那么该片段应该被移动到一个以该片段所做的事情命名的函数中。
<ins>该名称应该是一个动词，说明函数做什么</ins>，并允许调用序列读起来 “像写得好的散文”。²

² Grady Booch，私人邮件。

作为一个例子，考虑这个函数，改编自 JCommon 库。
它查找给定日期之前指定工作日的日期。
工作日代码是整数 1（星期日）到 7（星期六）。

```java
public static Date getPreviousDayOfWeek(int weekday, Date from) {
    // check arguments…
    if (!isValidWeekdayCode(weekday)) {
        throw new IllegalArgumentException(
            "Invalid day-of-the-week code."
        );
    }
    // find the date…
    final int adjust;
    final int baseDOW = from.getDayOfWeek();
    if (baseDOW > weekday) {
        adjust = Math.min(0, weekday - baseDOW);
    } else {
        adjust = -7 + Math.max(0, weekday - baseDOW);
    }
    return Date.addDays(adjust, from);
}
```

至少有两段代码片段，我们可以提取成更小、命名更好的函数。
而且这种提取将带来一些简化。

```java
public static Date getPreviousDayOfWeek(int weekday, Date from) {
    checkWeekdayArgument(weekday);
    return addDays(-daysBefore(weekday, from), from);
}

private static void checkWeekdayArgument(int weekday) {
    if (!isValidWeekdayCode(weekday))
        throw new IllegalArgumentException("Invalid day-of-the-week code.");
}

private static int daysBefore(int targetWeekday, Date from) {
    int fromWeekday = from.getDayOfWeek();
    int diff = fromWeekday - targetWeekday;
    return diff + (diff > 0 ? 0 : 7);
}
```

注意简化后的 `getPreviousDayOfWeek` 函数读起来如何。
它简短且清晰。
如果你需要了解更多，你只需往下看，就能看到提取出的函数。
然而，大多数情况下你不需要了解更多。
你只需看看那个函数，认同它，然后继续前进。
它可能读起来不像克莱顿小说的散文，但读起来相当不错。
