# 第 28 章 伤害

> 1. 我不会产生有害的代码。

软件专业人士的第一个承诺是：**不作恶！** 这意味着你的代码不得伤害你的用户、你的雇主、你的经理或你的程序员同行。

你必须知道你的代码做什么。
你必须知道它能工作。
你必须知道它是整洁的。

不久前，发现大众汽车的一些程序员编写了一些代码，故意阻挠 EPA 排放测试。
那些程序员编写了有害的代码。

它是有害的，因为它是欺骗性的。
那段代码欺骗了 EPA，允许销售排放的有害氮氧化物是 EPA 认为安全水平的 20 倍的汽车。
因此，那段代码可能伤害了所有居住在这些汽车行驶地区的人的健康。

那些程序员应该受到什么处罚？
他们知道那段代码的目的吗？
他们应该知道吗？

我会解雇他们并起诉他们。
因为无论他们是否知道，他们都应该知道。
躲在别人写的需求后面不是借口。
是我们的手指在键盘上。
是我们的代码。
我们必须知道它做什么！

这是一个艰难的问题，不是吗？
我们编写使机器工作的代码。
而这些机器往往处于能够造成巨大伤害的位置。
由于我们将对我们代码造成的任何伤害负责，我们必须负责知道我们的代码将做什么。

每个程序员都应该根据他们的经验和责任水平承担责任。
随着你在经验和职位上的提升，你对自己行为和你所负责人员行为的责任也随之增加。

显然，我们不能让初级程序员像团队领导那样负责。
我们不能让团队领导像资深开发人员那样负责。
但那些资深人员应该被要求达到很高的标准，并对他们指导的人承担最终责任。

这并不意味着所有责任都归于资深开发人员或经理。
每个程序员都有责任根据他们的成熟度和理解水平知道代码做什么。
每个程序员都对他们代码造成的伤害负责。
