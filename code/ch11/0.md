# 第 11 章 礼貌待人

<center><img src="../imgs/fig-ch11-0.png" width="40%" /></center><br/>

<ins>我们希望我们的模块是有礼貌的。
有礼貌的模块遵循 Ward Cunningham 对整洁的定义。
当你阅读代码时，你会发现它 “几乎是你所期望的”</ins>。
一个模块是一组有边界的函数和变量。
这可能由一个类、几个类或根本没有类组成。
重要的是函数和变量。
一个模块也可能包含在一个源文件或多个源文件中。
重要的是函数和变量的内聚性，而不是分隔它们的人为边界。
模块的另一个常见词是组件。

如果你大致遵循 “提取到底” 的做法，那么你的模块将由少数公共函数和许多从公共函数中提取出来的私有函数组成。
同样，这些可以被组织成类，以便你的模块包含一些公共类和几个私有类。

公共函数（可能被组织成公共类）代表了你模块的接口。
私有函数（也可能被组织成私有类）代表了你模块的实现。

<ins>借用 John Ousterhout 的精彩著作《A Philosophy of
Software Design》¹ 中的一个概念，那个模块有一个狭窄的接口和一个深层的实现 —— 这是一件好事</ins>。

¹ [APOSD](../bib.md#aposd) 。

<ins>现在，选择其中一个公共函数。
它在模块的最高层执行一个任务。
该函数的名称应该以抽象术语标识该任务</ins>。
例如，考虑前一章中 `RentalStatement` 类的 `makeStatement` 函数。

```go
func (statement *RentalStatement) makeStatement() string {
    statement.clearTotals()
    return statement.makeHeader() +
        statement.makeDetails() +
        statement.makeFooter()
}
```

函数的名称是抽象的。
它告诉你函数做什么，但不告诉函数如何做。
查看 `makeStatement` 函数内部，我们看到四个对从其中提取的私有函数的调用。
这些名称中的每一个也是抽象的，但处于比 `makeStatement` 更低的层次。
让我们看看 `clearTotals`。

```go
func (statement *RentalStatement) clearTotals() {
    statement.totalAmount = 0.0
    statement.frequentRenterPoints = 0
}
```

我们不能继续深入了。
我们已经到达了函数调用链的末端。
`clearTotals` 的实现精确地告诉我们如何清除总额，详细得令人痛苦。
没有更低的有意义的层次可以下降。

让我们转而看看 `makeDetails`。

```go
func (statement *RentalStatement) makeDetails() string {
    rentalDetails := ""
    for _, rental := range statement.rentals {
        rentalDetails += statement.makeDetail(rental)
    }
    return rentalDetails
}
```

这个函数的名称告诉我们在当前抽象层次上函数做了什么。
实现创建了一个循环，调用另一个私有方法 `makeDetail`，它低一个抽象层次。

<ins>因此，每个公共函数都会创建一个对较低抽象层次私有函数的调用树</ins>。

<ins>这里，我们再次看到 *步降规则 (The Stepdown Rule)* 。
每次这样的下降调用都下降一个抽象层次。
不是两个，不是三个。只有一个。
这就是为什么 `makeDetails` 内的循环体调用下一个函数的原因。
如果我把 `makeDetail` 的实现放在 `makeDetails` 内部，那么 `makeDetails` 将包含至少两个抽象层次</ins>。

我总是遵循那条规则吗？
不，有时我允许一个函数内有两个抽象层次。
但总的来说，我认为那是不礼貌的。
