你应该注意让你的代码格式良好。
你应该选择一套简单的规则来管理代码的格式，然后你应该始终如一地应用这些规则。
如果你在一个团队中工作，那么团队应该同意一套单一的格式化规则，并且所有成员都应该遵守。
拥有一个可以为你应用这些格式化规则的自动化工具会有所帮助。

## 格式化的目的

代码格式化很重要。
它重要到不容忽视，也重要到不应教条化地对待。
代码格式化关乎沟通，而沟通是专业开发者的首要任务。

也许你认为 “让它工作” 是专业开发者的首要任务。
我希望这本书已经开始让你摆脱这种想法。
你今天创建的功能在下一个版本中很可能会发生变化，但代码的可读性将对所有将要进行的更改产生深远的影响。
编码风格和可读性树立了先例，即使在原始代码被更改得面目全非之后，它们仍然持续影响着可维护性和可扩展性。
你的风格和纪律得以幸存，即使你的代码不复存在。
