## 团队规则

本节标题是一个文字游戏。
每个程序员都有自己偏好的格式化规则，但如果他们在团队中工作，那么团队规则（team rules，即团队说了算）。

一个开发团队应该就一种统一的格式化风格达成一致，然后团队中的每个成员都应该使用那种风格。
我们希望软件具有一致的风格。
我们不希望它看起来像是出自一群意见不一的个体之手。

当我在 2002 年启动 FitNesse 项目时，我与团队坐下来制定了一种编码风格。
这花了大约十分钟。
我们决定把大括号放在哪里，缩进大小是多少，如何命名类、变量和方法等等。
然后，我们将这些规则编码到我们 IDE 的代码格式化器中，并从此一直坚持使用。
这些并不是我偏好的规则；它们是团队决定的规则。
作为那个团队的一员，我在 FitNesse 项目中编写代码时遵循了它们。

记住，一个好的软件系统的源代码是一组可读性良好的文档。
它们需要有一致而流畅的风格。
读者需要能够相信他们在一个源文件中看到的格式手势在另一个文件中会有相同的含义。
我们最不想做的事情就是通过用一堆不同的个人风格来编写代码，从而给源代码增加更多的复杂性。
