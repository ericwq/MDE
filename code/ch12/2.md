## 数据抽象

我们倾向于将变量保持私有是有原因的。
我们不希望其他任何人依赖它们。
我们希望保持自由，以便随时更改它们的类型或实现。
那么，为什么这么多程序员会自动给他们的对象添加 getter 和 setter，将他们的私有变量暴露得像公共变量一样？

考虑下面 `Point 1` 和 `Point 2` 之间的区别。
两者都表示笛卡尔平面上一个点的数据。
然而，一个暴露了它的实现，而另一个完全隐藏了它。

———Point 1———

```java
public class Point {
    public double x;
    public double y;
}
```

———Point 2———

```java
public interface Point {
    double getX();
    double getY();
    void setCartesian(double x, double y);
    double getR();
    double getTheta();
    void setPolar(double r, double theta);
}
```

`Point 2` 的优美之处在于，你无法判断其实现是使用直角坐标还是极坐标。
它可能两者都不是！
该接口表示一个抽象数据结构。
我们可以知道在某个地方必须有一个数据结构，但我们不知道那个数据结构采取什么形式。

但 `Point 2` 不仅仅代表一个数据结构。
它还代表了行为策略。
尽管 getter 方法允许你访问单个坐标值，但两个 setter 方法强制执行两个坐标值作为一个原子操作一起被设置的策略。

另一方面，`Point 1` 非常明显是用直角坐标实现的，并且它迫使我们独立地操作坐标值。这暴露了实现。
实际上，即使变量是私有的，并且我们使用单变量的 getter 和 setter，它也会暴露实现。

<ins>隐藏实现不仅仅是在变量之间放置一层函数的问题。
隐藏实现是关于抽象的！
一个类不仅仅是通过 getter 和 setter 将其变量推出。
相反，它暴露抽象接口，允许其用户操作数据的本质，而无需知道数据是如何实现的</ins>。

考虑下面的 `Vehicle 1` 和 `Vehicle 2`。
第一个使用具体术语来传达车辆的燃料水平，而第二个使用百分比抽象来做到这一点。
在具体情况下，你可以相当肯定这些只是变量的访问器。
在抽象情况下，你对数据的形式一无所知。

———Vehicle 1———

```java
public interface Vehicle {
    double getFuelTankCapacityInGallons();
    double getGallonsOfGasoline();
}
```

———Vehicle 2———

```java
public interface Vehicle {
    double getPercentFuelRemaining();
}
```

在上述两种情况下，第二种选择更可取。
我们不想暴露数据的细节。
相反，我们想用抽象的术语来表达我们的数据。
这不仅仅是通过使用接口和/或 getter 和 setter 来实现的。
需要认真思考最好的方式来表现对象所包含的数据。
最糟糕的选择是轻率地添加 getter 和 setter。
