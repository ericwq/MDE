# 5 重构

> 在富足的世界里，唯一变得稀缺的因素是人类的注意力。
> <p align="right">——Kevin Kelly，《连线》杂志</p>

本章是关于人类注意力的。
它是关于关注你在做什么，并确保你尽力而为。
它是关于让某件事工作和让它正确之间的区别。
它是关于我们对代码结构所赋予的价值。

在他的经典著作《Refactoring》中，Martin Fowler 将重构定义为 “……改变一个软件系统的过程，使其不改变代码的外部行为，但改善其内部结构。”¹
但我们为什么要改进工作代码的结构呢？
那句老话 “如果没坏，就不要修它” 呢？

每个软件模块都有三个功能。
首先，是它在执行时执行的功能。
这个功能是模块存在的原因。
模块的第二个功能是适应变化。
几乎所有的模块都会在其生命周期中发生变化，开发人员有责任确保这种变化尽可能简单地进行。
一个难以改变的模块是坏的，需要修复，即使它能工作。
模块的第三个功能是与阅读者沟通。
不熟悉该模块的开发人员应该能够阅读和理解它，而无需过度的脑力劳动。
一个不沟通的模块是坏的，需要修复。

¹ [Fowler99]，第 xvi 页。

这个程序生成质数。
它是一个大的函数，有许多单字母变量和注释来帮助我们阅读它。

² 我最初在 XP Immersion I 上使用 Jim Newkirk 编写的测试编写了这个程序。
Kent Beck 和 Jim Newkirk 在学生面前重构了它。
我在这里试图重现那个重构。

Listing 5-1 GeneratePrimes.java 版本1

```java
/**
 * This class generates prime numbers up to a user-specified
 * maximum. The algorithm used is the Sieve of Eratosthenes.
 * <p>
 * Eratosthenes of Cyrene, b. c. 276 BC, Cyrene, Libya --
 * d. c. 194, Alexandria. The first man to calculate the
 * circumference of the Earth. Also known for working on
 * calendars with leap years, he ran the library at Alexandria.
 * <p>
 * The algorithm is quite simple. Given an array of integers
 * starting at 2. Cross out all multiples of 2. Find the next
 * uncrossed integer, and cross out all of its multiples.
 * Repeat until you have passed the square root of the maximum
 * value.
 *
 * @author Robert C. Martin
 * @version 9 Dec 1999 rcm
 */
import java.util.*;

public class GeneratePrimes
{
    /**
     * @param maxValue is the generation limit.
     */
    public static int[] generatePrimes(int maxValue)
    {
        if (maxValue >= 2) // the only valid case
        {
            // declarations
            int s = maxValue + 1; // size of array
            boolean[] f = new boolean[s];
            int i;
            // initialize array to true.
            for (i = 0; i < s; i++)
                f[i] = true;
            // get rid of known non-primes
            f[0] = f[1] = false;
            // sieve
            int j;
            for (i = 2; i < Math.sqrt(s) + 1; i++)
            {
                if (f[i]) // if i is uncrossed, cross its multiples.
                {
                    for (j = 2 * i; j < s; j += i)
                        f[j] = false; // multiple is not prime
                }
            }
            // how many primes are there?
            int count = 0;
            for (i = 0; i < s; i++)
            {
                if (f[i])
                    count++; // bump count.
            }
            int[] primes = new int[count];
            // move the primes into the result
            for (i = 0, j = 0; i < s; i++)
            {
                if (f[i]) // if prime
                    primes[j++] = i;
            }
            return primes; // return the primes
        }
        else // maxValue < 2
            return new int[0]; // return null array if bad input.
    }
}
```

在第三种情况下应该有两个质数，即 2 和 3 。
在最后一种情况下应该有 25 个质数，最后一个是97 。
如果所有这些测试都通过，那么我假设生成器是工作的。
我怀疑这不是万无一失的，但我想不出一个合理的场景，在这些测试通过的情况下函数会失败。

Listing 5-3 PrimeGenerator.java，版本2

```java
/**
 * This class generates prime numbers up to a user-specified
 * maximum. The algorithm used is the Sieve of Eratosthenes.
 * Given an array of integers starting at 2:
 * Find the first uncrossed integer, and cross out all its
 * multiples. Repeat until the first uncrossed integer exceeds
 * the square root of the maximum value.
 */
import java.util.*;

public class PrimeGenerator
{
    private static int s;
    private static boolean[] f;
    private static int[] primes;

    public static int[] generatePrimes(int maxValue)
    {
        if (maxValue < 2)
            return new int[0];
        else
        {
            initializeSieve(maxValue);
            sieve();
            loadPrimes();
            return primes; // return the primes
        }
    }

    private static void loadPrimes()
    {
        int i;
        int j;
        // how many primes are there?
        int count = 0;
        for (i = 0; i < s; i++)
        {
            if (f[i])
                count++; // bump count.
        }
        primes = new int[count];
        // move the primes into the result
        for (i = 0, j = 0; i < s; i++)
        {
            if (f[i]) // if prime
                primes[j++] = i;
        }
    }

    private static void sieve()
    {
        int i;
        int j;
        for (i = 2; i < Math.sqrt(s) + 1; i++)
        {
            if (f[i]) // if i is uncrossed, cross out its multiples.
            {
                for (j = 2 * i; j < s; j += i)
                    f[j] = false; // multiple is not prime
            }
        }
    }

    private static void initializeSieve(int maxValue)
    {
        // declarations
        s = maxValue + 1; // size of array
        f = new boolean[s];
        int i;
        // initialize array to true.
        for (i = 0; i < s; i++)
            f[i] = true;
        // get rid of known non-primes
        f[0] = f[1] = false;
    }
}
```

`initializeSieve` 函数有点混乱，所以在 Listing 5-4 中，我相当程度上清理了它。
首先，我所有使用 `s` 变量的地方替换为 `f.length`。
然后，我将三个函数的名称改为更具表现力的名称。
最后，我重新安排了 `initializeArrayOfIntegers`（原名 `initializeSieve`）的内部结构，使其读起来更好一些。
所有测试仍然通过。

```java
{
    private static boolean[] f;
    private static int[] result;

    public static int[] generatePrimes(int maxValue)
    {

            return new int[0];
        else
        {
            initializeArrayOfIntegers(maxValue);
            crossOutMultiples();
            putUncrossedIntegersIntoResult();
            return result;
        }

    private static void initializeArrayOfIntegers(int maxValue)
    {
        f = new boolean[maxValue + 1];
        f[0] = f[1] = false; //neither primes nor multiples.
        for (int i = 2; i < f.length; i++)
            f[i] = true;
    }

```

接下来，我检查了 `crossOutMultiples`。
在这个函数和其他函数中有一些语句的形式是 `if(f[i] == true)`。
意图是检查 i 是否未被划掉，所以我把 `f` 的名字改成了 `unCrossed`。
但这导致了像 `unCrossed[i] = false` 这样丑陋的语句。
我发现双重否定令人困惑。
所以我把数组的名字改成了 `isCrossed`，并改变了所有布尔值的含义。
所有测试仍然通过。

我摆脱了将 `isCrossed[0]` 和 `isCrossed[1]` 设置为 `true` 的初始化，只是确保函数的任何部分都不会对小于 2 的索引使用 `isCrossed` 数组。
我提取了 `crossOutMultiples` 函数的内部循环，并将其称为 `crossOutMultiplesOf`。
我还认为 `if(isCrossed[i] == false)` 令人困惑，所以我创建了一个名为 `notCrossed` 的函数，并将 `if` 语句改为 `if (notCrossed(i))`。
所有测试仍然通过。

我花了一些时间写了一个注释，试图解释为什么你只需要迭代到数组大小的平方根。
这促使我将计算提取到一个函数中，在那里我可以放置解释性的注释。
在写注释时，我意识到平方根是数组中任何整数的最大质因数。
所以我为处理它的变量和函数选择了那个名字。
所有这些重构的结果在 Listing 5-5 中。
所有测试仍然通过。

Listing 5-5 PrimeGenerator.java 版本4（部分）

```java
public class PrimeGenerator
{
    private static boolean[] isCrossed;
    private static int[] result;

    public static int[] generatePrimes(int maxValue)
    {
        if (maxValue < 2)
            return new int[0];
        else
        {
            initializeArrayOfIntegers(maxValue);
            crossOutMultiples();
            putUncrossedIntegersIntoResult();
            return result;
        }
    }

    private static void initializeArrayOfIntegers(int maxValue)
    {
        isCrossed = new boolean[maxValue + 1];
        for (int i = 2; i < isCrossed.length; i++)
            isCrossed[i] = false;
    }

    private static void crossOutMultiples()
    {
        int maxPrimeFactor = calcMaxPrimeFactor();
        for (int i = 2; i <= maxPrimeFactor; i++)
            if (notCrossed(i))
                crossOutMultiplesOf(i);
    }

    private static int calcMaxPrimeFactor()
    {
        // We cross out all multiples of p, where p is prime.
        // Thus, all crossed out multiples have p and q for
        // factors. If p > sqrt of the size of the array, then
        // q will never be greater than 1. Thus p is the
        // largest prime factor in the array, and is also
        // the iteration limit.
        double maxPrimeFactor = Math.sqrt(isCrossed.length) + 1;
        return (int) maxPrimeFactor;
    }

    private static void crossOutMultiplesOf(int i)
    {
        for (int multiple = 2*i;
             multiple < isCrossed.length;
             multiple += i)
            isCrossed[multiple] = true;
    }

    private static boolean notCrossed(int i)
    {
        return isCrossed[i] == false;
    }
}
```

最后一个要重构的函数是 `putUncrossedIntegersIntoResult`。
这个方法有两部分。
第一部分计算数组中未被划掉的整数数量，并创建该大小的结果数组。
第二部分将未被划掉的整数移动到结果数组中。
我将第一部分提取到它自己的函数中，并进行了一些杂项清理。
所有测试仍然通过。

### 最后的重读

<img src="../imgs/fig-ch5-1.png" width="50%"/><br/>

接下来，我对整个程序做了最后一次检查，从头到尾读了一遍，就像阅读几何证明一样。
这是一个重要的步骤。

到目前为止，我一直在重构片段。
现在，我想看看整个程序是否作为一个可读的整体结合在一起。

首先，我意识到我不喜欢 `initializeArrayOfIntegers` 这个名字。
实际上被初始化的不是一个整数数组，而是一个布尔数组。
然而，`initializeArrayOfBooleans` 也不是一个改进。
我们在这个方法中真正做的是 “划开” 所有相关的整数，以便我们可以划掉它们的倍数。
所以我将名称改为 `uncrossIntegersUpTo`。
我还意识到我不喜欢布尔数组的名称 `isCrossed`。
所以我将其改为 `crossedOut`。
所有测试仍然通过。

有人可能会认为我对这些名称更改是轻率的，但有了重构浏览器，你可以负担得起做这类调整 —— 它们几乎不花费任何成本。
即使没有重构浏览器，简单的查找和替换也相当便宜。
而且测试强烈地减少了我们可能在不知情的情况下破坏某些东西的机会。

我不知道我写那些 `maxPrimeFactor` 相关的东西时抽了什么风。
哎呀！数组大小的平方根不一定是质数。
那个方法并没有计算最大质因数。
解释性的注释是错误的。
所以我重写了注释，更好地解释平方根背后的原理，并适当地重命名了所有变量。³
所有测试仍然通过。

³ 当 Kent Beck 和 Jim Newkirk 重构这个程序时，他们完全去掉了平方根。
Kent 的理由是平方根难以理解，而且如果你一直迭代到数组大小，也没有测试会失败。
我无法让自己放弃这种效率。
我想这显示了我的汇编语言根源。

那个 `+1` 到底在那里干什么？
我想那一定是偏执。
我担心一个带小数的平方根会转换成一个太小的整数，无法作为迭代限制。
但那是愚蠢的。
真正的迭代限制是小于或等于数组大小平方根的最大质数。
我会去掉那个 `+1`。

测试都通过了，但最后的改变让我相当紧张。
我理解平方根背后的原理，但我有一种挥之不去的感觉，可能有一些边缘情况没有被覆盖。
所以我会写另一个测试来检查在 2 到 500 之间的任何质数列表中都没有倍数。
（参见 Listing 5-8 中的 `testExhaustive` 函数。）新的测试通过了，我的恐惧得到了缓解。

代码的其余部分读起来相当好。
所以我认为我们完成了。
最终版本如 Listing 5-7 和 5-8 所示。

Listing 5-7 PrimeGenerator.java (最终版)

```java
/**
 * This class generates prime numbers up to a user specified
 * maximum. The algorithm used is the Sieve of Eratosthenes.
 * Given an array of integers starting at 2:
 * Find the first uncrossed integer, and cross out all its
 * multiples. Repeat until there are no more multiples
 * in the array.
 */
public class PrimeGenerator
{
    private static boolean[] crossedOut;
    private static int[] result;

    public static int[] generatePrimes(int maxValue)
    {
        if (maxValue < 2)
            return new int[0];
        else
        {
            uncrossIntegersUpTo(maxValue);
            crossOutMultiples();
            putUncrossedIntegersIntoResult();
            return result;
        }
    }

    private static void uncrossIntegersUpTo(int maxValue)
    {
        crossedOut = new boolean[maxValue + 1];
        for (int i = 2; i < crossedOut.length; i++)
            crossedOut[i] = false;
    }

    private static void crossOutMultiples()
    {
        int limit = determineIterationLimit();
        for (int i = 2; i <= limit; i++)
            if (notCrossed(i))
                crossOutMultiplesOf(i);
    }

    private static int determineIterationLimit()
    {
        // Every multiple in the array has a prime factor that
        // is less than or equal to the sqrt of the array size,
        // so we don't have to cross out multiples of numbers
        // larger than that root.
        double iterationLimit = Math.sqrt(crossedOut.length);
        return (int) iterationLimit;
    }

    private static void crossOutMultiplesOf(int i)
    {
        for (int multiple = 2*i;
             multiple < crossedOut.length;
             multiple += i)
            crossedOut[multiple] = true;
    }

    private static boolean notCrossed(int i)
    {
        return crossedOut[i] == false;
    }

    private static void putUncrossedIntegersIntoResult()
    {
        result = new int[numberOfUncrossedIntegers()];
        for (int j = 0, i = 2; i < crossedOut.length; i++)
            if (notCrossed(i))
                result[j++] = i;
    }

    private static int numberOfUncrossedIntegers()
    {
        int count = 0;
        for (int i = 2; i < crossedOut.length; i++)
            if (notCrossed(i))
                count++;
        return count;
    }
}
```

```java
        for (int i=0; i<list.length; i++)
```

## 结论

这个程序的最终结果读起来比开始时好得多。
程序的工作效果也好了一点。
我对结果相当满意。
程序更容易理解，因此也更容易更改。
而且，程序的结构将其各部分彼此隔离。
这也使得程序更容易更改。

你可能会担心提取只被调用一次的函数会对性能产生不利影响。
我认为在大多数情况下，增加的可读性值得那几纳秒。
然而，可能有一些深层的内循环，那几纳秒会代价高昂。
我的建议是假设成本可以忽略不计，并等待被证明是错误的。

这值得我们在其中投入的时间吗？
毕竟，函数在我们开始时是工作的。
我强烈建议你对你编写的每个模块和你维护的每个模块都练习这种重构。
与你在不久的将来为自己和他人节省的努力相比，时间投入非常小。

重构就像晚餐后清理厨房。
你第一次跳过它，你更快地完成了晚餐。
但是缺乏干净的盘子和清晰的工作空间使得第二天的晚餐准备时间更长。
这让你想再次跳过清理。
实际上，如果你今天跳过清理，你总是可以更快地完成晚餐，但混乱会累积。
最终，你花费了过多的时间寻找合适的烹饪用具，凿掉盘子上结壳的干食物，并擦洗它们使它们适合烹饪。
晚餐永远做不完。
跳过清理并不会真正使晚餐更快。

本章所描述的重构的目标是每天清理你的代码。
我们不希望混乱积累。
我们不想必须凿掉和擦洗随时间积累的结壳碎片。
我们希望能够以最小的努力扩展和修改我们的系统。
这种能力最重要的推动者是代码的整洁。

我无法强调这一点。
如果所应用的原则和模式的代码是一团糟，那么这本书中的所有原则和模式都将化为乌有。
在投资原则和模式之前，先投资于整洁代码。
