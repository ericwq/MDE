# 第 1 章 引言

如果你从没听说过一本叫《Design Patterns: Elements of Reusable Object-Oriented Software》的书 [GoF95](../biblio.md#gof95)，那么在继续往下读之前，眼下正是弄一本来看看的大好时机。
如果你听说过那本书，甚至可能就有一本，却从没真正*研读*过，情况也一样。

如果你还在跟着我往下读，我就假定你不属于这两种情况。
也就是说，你对模式大体上有点了解，对我们那 23 个设计模式尤其如此。
要有这个底子，你才能从《Pattern Hatching》中获益，因为它扩展、更新并以别的方式增补了《Design Patterns》的内容。
如果你不熟悉所谓 GoF 的那些模式——也就是前面提到的 23 个——这里的洞见大多对你是封闭的。
事实上，读这本书时手边放一本《Design Patterns》会很有帮助。
我还假定你熟稔 C++；这个假定应当算合理，因为我们在《Design Patterns》里也做了同样的假定。

那么，请你原谅我多此一举，作为一次现实检验：看你能不能用 25 个词以内说出 COMPOSITE 模式的意图。
你也许想先转过头去，想上一分钟。

<p align="center">❖ ❖ ❖</p>

那句意图是不是一字不差地从你嘴里溜了出来？
如果是，你在这里不会有什么麻烦。
说真的，你对这玩意儿恐怕*太认真*了。
不妨培养一两个爱好。
如果你知道那句意图，只是说不利索，别担心——这本书也是为你写的。

不过，如果你脑子里一片空白，那我开头那段就彻底辜负了我们俩。
我建议你放下这本书，拿起一本《Design Patterns》，翻到第 163 页，一直读到 "实现" 一节的末尾。
对那本书第 xv 页列出的其他模式也照此办理。
这番功课应当能给你足够的底子，让这本书对得起你花的时间。

你可能会问：为什么叫 "Pattern Hatching"？
我最初选这个书名，是因为它像计算机科学里一个耳熟能详的概念。
（再说，好听的名字都被别的模式书占去了。）
但后来我慢慢觉得，它相当准确地抓住了我对这批材料的用意。
*孵化*并不暗示我们在创造什么；它暗示的是从既有的胚芽发育出来。
而这恰好很贴切：打个比方，《Design Patterns》就是我们那盒鸡蛋，但愿会有许多新生命从中孵出来。¹

¹：我相信我们不会有太多机会把这个类比继续引申下去。

> 译注：*Pattern Hatching* 与计算机科学中的 *Pattern Matching*（模式匹配）谐音，所以作者说 "它像计算机科学里一个耳熟能详的概念"；而 *hatching* 的本义是禽蛋 "孵化"，与下文 "一盒鸡蛋" 的比喻一脉相承。

请放心，我在这里并不是单纯地附和《Design Patterns》。
<ins>我的目标是在它之上添砖加瓦，借它的概念发力，让这些概念对你更有用。
你会找到一些技巧：视情形而定，哪些模式该用，哪些不该用。
你会碰到关于我们原有模式的一些新洞见，也会亲眼看到我们开发新模式的过程。</ins>
例子也很多。
有些是久经考验的设计；有些是实验性的——那是 "半生不熟" 的一种好听说法。
还有些纯粹出于推想——不加掩饰的纸上设计，放到现实的强光下大概会枯萎，但它们也可能含有更健壮设计的种子。

<ins>我把这些东西摆到你面前，是真心希望你的设计感觉更深、模式意识更强、对软件开发的看法更开阔。
这些都是我使用模式的亲身经历。
我希望它们也能成为你的。</ins>
