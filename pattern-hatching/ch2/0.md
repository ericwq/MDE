# 第 2 章 用模式做设计

体会怎样使用模式，最好的办法——嗯，就是*真的去用*它们。
难题落在我身上：得想出一个所有人都能领会的例子。
人最关心的是自己的问题；而一个例子对某人越有趣，往往就越专门。
麻烦在于，这类例子通常处理的是冷僻的问题，非本行的人很难弄懂。

<ins>所以我们不妨考虑设计一样每个计算机用户都该熟悉的东西：层次化的文件系统。
我们不打算纠缠 I/O 缓冲、磁盘扇区管理这类底层实现问题。
我们要设计的是应用开发者所用的编程模型，也就是文件系统的应用程序编程接口，即 API。</ins>
多数操作系统里，这个 API 由几十个过程调用和一些数据结构组成，几乎没给扩展留出余地。
我们的设计则完全面向对象、可扩展。

我先聚焦于设计中的两个特别重要的方面，以及应对它们的模式。
然后在这个例子上继续搭建，向你展示其他模式如何应对各种设计问题。
<ins>这里的目的既不是规定一套僵硬的模式应用流程，也不是示范设计文件系统的最佳做法；而是鼓励你自己动手使用模式。</ins>
你用模式、看别人用模式，用得越多，就越觉得顺手。
最终你会掌握应用模式的完美技巧：你自己的那一套。
