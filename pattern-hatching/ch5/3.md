# 5.3 习惯 3：尽早且频繁地具体化

在我们那些模式里，动机一节排在最前面。
因为，先把概念用具体的方式讲一遍、再用更抽象的方式讲，人们似乎理解得更好。
动机一节里的具体例子，给读者提供了理解该问题及其解法的参照系。
这一节还演示了另一点：为什么其它路子都行不通——同样是用具体的方式。
有了动机一节作引子，读者就更能领会那个一般的解法。

具体化的一条推论是：需要大量来自现实世界的例子。
例子*不该*只是动机一节的领地。
在整篇模式里用正例与反例来说明要点。
就连我们模板里最抽象的几节（即适用性、结构、参与者、协作）有时也会带例子。
比如，有些协作一节会带交互图，显示对象在运行期如何通信。
在讨论模式的抽象方面时，回头引用这些例子——即便在讲抽象，也要具体。

另一条推论可以称作 "把实情全说出来"。
意思是：你必须提醒读者这个模式可能有哪些坑。
渲染它的好处实在太容易；而要真正看清一个模式的短处并坦率地谈，就不那么容易了。
没有哪个模式没有缺点，不管是额外的开销、特定情形下的不良行为，还是别的什么。
务必让读者明白这个模式会在哪里力有不逮。
