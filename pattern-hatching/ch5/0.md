# 第 5 章 高效模式写作者的七个习惯

如果你觉得面向对象开发已经很难做好，那就试试 *模式* 开发！
我骨子里那个数学家喜欢把它看作面向对象设计的 "积分"：它是无数细小经验在一段应用区间上的累加。
然而模式开发似乎比我在微积分课上学到的要难得多。
积分彼此互不干扰，因此可以逐个求解（不过，懂得怎么解其中一个，往往有助于解出其他几个）。
相比之下，模式不能在真空里工作。
它只提供一个问题的解，因此必须与其他模式协作。
所以，模式写作者要琢磨的不是一个模式，而是好几个，甚至包括一些尚未写出来的模式——而这只是模式开发过程中诸多挑战之一。
如果你有志于写模式，那么一切能得到的帮助你都需要。

写《Design Patterns》的时候，我们确实在模式开发上学到很多。
从上一章你大概已经看出来，我们至今还在学。
在这收尾的一章里，我试图把我们的经验浓缩成七个习惯——它们是我们多年来写模式时，多半不自觉地养成的。
把这些习惯放在心上，能帮你比我们当年更快地练就写模式的本事。
